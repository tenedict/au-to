# 비기능 요구사항 정의서 (SRS)

> BMAD Phase 2 · `bmad-prd` 의 비기능 요구사항.
> 성능·프라이버시·접근성·유지보수는 기능이 다 돌아도 제품을 못 쓰게 만들 수 있다.

| 항목 | 값 |
| --- | --- |
| 문서 버전 | 1.0 |
| 최종 수정 | 2026-08-01 |
| 대상 | iOS 17.0+ · iPhone |

## 1. 성능 (NFR-PERF)

| ID | 요구사항 | 목표 | 상태 |
| --- | --- | --- | --- |
| NFR-PERF-01 | 공유 시트에서 "담았어요"까지 | 1초 이내 | 🟡 실기기 미측정 |
| NFR-PERF-02 | 스크린샷 1장 OCR | 1.5초 이내 | 🟡 |
| NFR-PERF-03 | 백엔드 분석 왕복 | 5초 이내 (p50) | 🟡 |
| NFR-PERF-04 | 공유 시작 → 확인 완료 중앙값 | 15초 이내 | 🟡 |
| NFR-PERF-05 | 목록 스크롤 | 60fps 유지 | 🟡 |
| NFR-PERF-06 | OCR·분석이 메인 스레드를 막지 않는다 | 항상 | ✅ |

**NFR-PERF-06이 없으면 나머지 숫자가 의미를 잃는다.** 인식이 메인 스레드에서 돌면
여러 장을 담아 둔 사용자에게 앱은 죽은 것처럼 보인다. `VisionOCRService`는
`VNImageRequestHandler.perform`을 반드시 배경 큐로 내보낸다.

### 타임아웃 예산

시간이 흐르는 방향으로 짧아진다. 안쪽이 더 길면 바깥쪽이 먼저 끊기고, 안쪽 작업은
아무도 결과를 기다리지 않는 채 계속 돈다.

```
iOS URLRequest.timeoutInterval   20초
  └ backend → OpenAI              15초   (REQUEST_TIMEOUT_MS)
```

## 2. 프라이버시 (NFR-PRIV)

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| NFR-PRIV-01 | OpenAI API 키는 앱·Extension 바이너리에 존재하지 않는다 | ✅ 프로젝트 규칙 2 |
| NFR-PRIV-02 | OCR은 온디바이스에서 한다. 원본 이미지는 기본적으로 기기를 떠나지 않는다 | ✅ |
| NFR-PRIV-03 | 백엔드는 `store: false`로 호출해 원문이 OpenAI에 남지 않게 한다 | ✅ |
| NFR-PRIV-04 | 서버 로그에 인식 원문을 기본 저장하지 않는다 | ✅ 코드 리뷰 |
| NFR-PRIV-05 | 담아 둔 스크린샷은 확인이 끝나면 지운다 | ✅ |
| NFR-PRIV-06 | 원본 스크린샷 보존 기간을 사용자가 정한다 | ⬜ 미결정 D-2 |

**스크린샷은 이 앱이 다루는 가장 민감한 데이터다.** 메신저 대화·예약 정보·주소가 그대로 들어 있다.
그래서 기본값은 언제나 "보내지 않는다"이고, 보내는 것은 OCR로 뽑은 텍스트뿐이다.

## 3. 접근성 (NFR-A11Y)

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| NFR-A11Y-01 | 색만으로 정보를 전달하지 않는다 | ✅ 묶음마다 기호+글자 |
| NFR-A11Y-02 | 인터랙티브 요소에 접근성 레이블이 있다 | ✅ |
| NFR-A11Y-03 | 지갑 카드는 VoiceOver에서 제목·마감·묶음을 한 번에 읽는다 | ✅ |
| NFR-A11Y-04 | 캘린더 날짜 칸은 점 대신 "마감 N개"를 읽는다 | ✅ |
| NFR-A11Y-05 | 비활성 컨트롤에 이유가 함께 보인다 | ✅ |
| NFR-A11Y-06 | 접근성 글자 크기에서 레이아웃이 깨지지 않는다 | ✅ |
| NFR-A11Y-07 | 모션 줄이기에서 카드 펼침 애니메이션을 줄인다 | ✅ |
| NFR-A11Y-08 | 대비 높이기 설정을 존중한다 | ✅ |
| NFR-A11Y-09 | 알림을 누르면 그 할 일로 간다 | ✅ |

**NFR-A11Y-06은 지갑 스택의 구조적 대가였다.** 겹침 계산을 순수 함수로 유지하려고
카드 높이를 고정값으로 뒀고, 글자가 커지면 내용이 잘렸다.

해소는 두 단계다. `.xxxLarge` 까지는 `WalletStackLayout.scaled(by:)` 로 세 값을
함께 키운다. **접근성 크기부터는 겹침을 포기하고** 평범한 목록으로 바꾼다 —
그 크기에서는 제목 한 줄과 마감 한 줄만으로도 겹침이 전제하는 공간을 넘기기 때문이다.

**NFR-A11Y-08은 겹침이 그림자에만 의존하던 것을 드러냈다.** 대비를 높인 사용자에게는
그림자가 거의 안 보여 겹친 카드가 하나의 긴 카드로 읽힌다. 그래서 그 설정에서는
그림자를 끄고 카드마다 테두리를 그린다.

## 7. 보안 (NFR-SEC)

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| NFR-SEC-01 | 백엔드 요청 본문 상한 128KB | ✅ |
| NFR-SEC-02 | 인식 원문 길이 상한 50,000자 | ✅ |
| NFR-SEC-03 | 업스트림 상태 코드를 그대로 흘리지 않는다 | ✅ |
| NFR-SEC-04 | 개발 기본 주소는 로컬 루프백이다 | ✅ `127.0.0.1` |
| NFR-SEC-05 | 백엔드 클라이언트 인증·rate limit | ✅ 공유 비밀 + IP/일일 한도 |
| NFR-SEC-06 | 배포 주소는 HTTPS | ✅ Cloud Run 자동 |
| NFR-SEC-07 | 비밀이 저장소에 커밋되지 않는다 | ✅ 프로젝트 규칙 11 |

**공유 비밀은 앱 번들을 뜯으면 나온다.** 그걸 알고 쓰는 방식이다 (SPEC H-3.2).
새는 것이 OpenAI 키가 **아니라** 이 값이라는 데 의미가 있다 — 교체하면 끝이고,
새더라도 요청 한도가 금액 피해를 제한한다.

진짜로 앱만 통과시키려면 App Attest 가 필요하다. MVP 범위 밖이다.

**한도는 인스턴스마다 따로 센다.** 실제 금액 상한은 `하루 한도 × 최대 인스턴스 수` 이고,
배포 스크립트가 `--max-instances` 를 고정한다.
