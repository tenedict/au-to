# S-5.10 ~ S-5.12 · 확인 요청 알림

> 완료 2026-08-01

---

## 요구

> "할일 목록이 추가되었어요 승인해주세요 뭐 이런 푸쉬가 떠야할듯??"

---

## 무엇이 문제였나

분석은 **메인 앱에서만** 돈다 (ADR-2 — Extension 은 담기만 한다).
그래서 공유 시트로 담고 앱을 열지 않으면:

```
스크린샷 공유 → 상자에 담김 → ...아무 일도 일어나지 않음
```

담은 것을 잊으면 **이 제품은 사진첩과 같아진다.** 사진첩에 묻히는 문제를 풀겠다고
만든 앱이 같은 방식으로 묻히는 셈이다.

---

## 되물어서 갈린 결정

| 질문 | 결정 | 왜 |
| --- | --- | --- |
| 누가 알리나? | **Share Extension 이 담은 직후** | 앱은 그 시점에 실행 중이 아니다 |
| ADR-2(Extension 은 수집만)를 어기나? | **아니오** | 막는 기준은 "무엇을 import 했나"가 아니라 "얼마나 오래 걸리나"다. 로컬 알림 예약은 파일 쓰기 한 번 수준이다 |
| 문구는? | **"스크린샷을 담았어요"** | 그 시점에는 아직 아무것도 읽지 않았다. "할 일을 만들었어요"는 열어 봤을 때 어긋난다 |
| "승인해주세요"? | **"확인해 주세요"** | 05-IA 용어 사전 — "승인"은 권한처럼 들린다 |
| 앱이 앞에 있을 때도 띄우나? | **아니오** | 확인 화면이 이미 떠 있다. 같은 말을 두 번 하면 잔소리다 |
| 확인 안 하고 나가면? | **1시간 뒤 한 번 더** | 곧바로면 잔소리, 하루 뒤면 이미 잊는다 |
| 권한은 언제 묻나? | **홈에서 직접 켤 수 있게** | 첫 저장까지 기다리면 **첫 공유의 알림을 놓친다** — 권한이 없으면 Extension 이 건 알림이 조용히 사라진다 |

## 태스크

### 1. `CaptureNotice` (5분)

- 파일 — `core/swift/Shared/CaptureNotice.swift` (새 파일)
- `Shared/` 인 이유 — Extension 타깃에도 들어가야 한다. `Services/` 는 안 들어간다
- `postCaptureTaken` · `scheduleUnconfirmedDrafts` · `clear` · `cancelUnconfirmedDrafts`
- 검증 — 2번

### 2. 식별자 충돌 테스트 — 🔴 RED (5분)

- 파일 — `tests/swift/CaptureNoticeTests.swift` (새 파일)
- **마감 알림이 확인 요청으로 분류되지 않는다** ← 이게 핵심이다
- 반대 방향도. 확인 요청이 마감 식별자와 겹치지 않는다
- 검증 — 6건 초록

> 겹치면 "앞에 있을 때 확인 요청은 안 띄운다"는 규칙이 마감 알림에도 적용돼
> **앱을 켜 둔 사용자가 마감을 그대로 놓친다.** 눈으로는 절대 못 잡는다.

### 3. Share Extension 연결 (2분)

- `SharedInbox.enqueue` 뒤 `CaptureNotice.postCaptureTaken`
- 검증 — 빌드 + 실기기 (M-11)

### 4. 프로젝트 규칙 3 좁히기 (3분)

- `UserNotifications` 를 금지 목록에서 뺀다. **이유를 주석에 적는다**
- `Vision` 을 넣어 보고 여전히 빨간불인지 확인
- 검증 — 일부러 어겨 보기

### 5. 프로젝트 규칙 7 좁히기 (3분)

- 규칙 7이 `CaptureNotice` 를 잡았다. **규칙이 제 일을 한 것이다**
- 허용 목록을 두 파일로 명시하고, 왜 둘인지 주석에 적는다
- 뷰에서 직접 예약해 보고 여전히 빨간불인지 확인
- 검증 — 일부러 어겨 보기

### 6. 앞에 있을 때 억제 + 탭 라우팅 (5분)

- `willPresent` — 확인 요청이면 `[]`
- `didReceive` — 확인 요청이면 할 일 탭 + 미뤄 둔 초안까지 되살린다
  (확인하러 온 사람에게 "나중에 확인" 상태를 남기면 안 된다)
- 검증 — 실기기

### 7. 알림 정리 (3분)

- 앱이 캡처를 손에 쥐면 `clear` — **전달된 것까지** 지운다
- 예약만 지우면 알림 센터에 남아 이미 처리한 것을 확인하러 다시 연다
- 검증 — 실기기 (M-12)

### 8. 미확인 초안 재알림 (3분)

- `scenePhase == .background` → `scheduleUnconfirmedDraftReminderIfNeeded()`
- `refresh()` 에서 취소 — 사용자가 지금 여기 있다
- 검증 — 실기기 (M-13)

### 9. 권한 옵트인 줄 (4분)

- `notDetermined` 이면 홈에 "알림을 켤까요?" 를 띄운다
- 무엇을 받게 되는지 함께 적는다
- 검증 — 시뮬레이터 (앱 지우고 새로 설치)

## 이 작업에서 규칙이 한 일

규칙 7(알림 예약은 서비스 한 곳에서만)이 `CaptureNotice` 를 **곧바로 잡았다.**

규칙을 지우거나 예외를 몰래 넣지 않고, 두 번째 자리가 왜 필요한지를 주석에 적고
허용 목록을 **두 파일로 명시**했다. 그리고 뷰에서 직접 예약해 보며
규칙이 여전히 잡는지 확인했다.

> 규칙이 걸리면 규칙을 끄는 게 아니라, 왜 예외인지를 적을 수 있는지 본다.
> 적을 수 없으면 그건 예외가 아니라 결함이다.
