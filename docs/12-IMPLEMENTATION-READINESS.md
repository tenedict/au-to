### B-2 를 특별히 적는 이유

백엔드 테스트 15건은 전부 `fetchImpl` 을 대역으로 바꿔 돈다. **실제 OpenAI 응답의
모양을 확인한 적이 없다.** `parseTaskDraftResponse` 가 `output[].content[].type === "output_text"`
를 가정하는데, 그 가정이 맞는지는 한 번 불러 봐야 안다.

> 사용자가 넣을 것은 `backend/.env` 의 `OPENAI_API_KEY` 한 줄뿐이다.
> 나머지는 전부 채워져 있다.

### 막지 않는 것

| 항목 | 왜 괜찮은가 |
| --- | --- |
| 중복 감지 (S-4.9) | 없어도 사용자가 지울 수 있다. 정책(D-5)이 먼저다 |
| 검색·필터 (S-4.10) | 할 일 개수가 적은 초기에는 스택으로 충분하다 |
| 캘린더 역동기화 | MVP 범위 밖 (ADR-7) |

| # | 항목 | 근거 |

| ~~F-1~~ | ~~접근성 글자 크기에서 카드가 잘린다~~ | ✅ S-9.1 |
| ~~F-2~~ | ~~모션 줄이기 미대응~~ | ✅ S-9.2 |
| ~~F-3~~ | ~~대비 높이기 미대응~~ | ✅ S-9.3 |
| ~~F-4~~ | ~~백엔드 인증·rate limit 없음~~ | ✅ 공유 비밀 + 한도 |
| F-5 | 평가셋 50건 없음 | S-2.3 · R-19 · R-20 위험이 무방비 |

**F-1 은 지갑 스택의 구조적 대가였다.** 겹침 계산을 순수 함수로 유지하려고 카드 높이를
고정값으로 뒀다. 배율만 키우는 것으로는 부족해서 — 접근성 크기에서는 마감 날짜가
두 줄로 넘쳐 다음 카드가 덮었다 — 그 크기부터는 **겹침 자체를 포기하고** 평범한
목록으로 바꿨다. 자세한 것은 [08-와이어프레임 §5](08-와이어프레임.md).

**F-4 없이는 배포할 수 없다.** 지금 백엔드는 주소를 아는 누구나 우리 키로 요청을
보낼 수 있다. 로컬 전용이라 문제가 없을 뿐이다.
