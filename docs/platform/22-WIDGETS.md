# 위젯 — 홈 화면과 잠금화면

> 홈 화면 위젯은 **읽는다**. 잠금화면 위젯은 **담는다.**
> 2026-08-03

---

## 0. 왜 둘인가

위젯이 둘이고 하는 일이 반대다.

| | 자리 | 하는 일 | 누르면 |
| --- | --- | --- | --- |
| `NextTaskWidget` | 홈 화면 | 다음 일정을 **읽는다** | 앱을 연다 |
| `CaptureLockWidget` | 잠금화면 | 눌러서 **담는다** | 카메라가 곧바로 뜬다 |

**하나로 합치지 않는다.** 홈 화면 위젯을 눌러도 카메라가 열리면, 일정을 확인하려고
누른 사용자가 매번 카메라를 닫아야 한다. 같은 제스처가 두 가지 뜻을 가지면
사용자는 누르기 전에 매번 생각해야 한다.

---

## 1. 홈 화면 — 다음 일정

```
┌───────────────┐  ┌───────────────────────────────┐
│ ◌ 다음 일정 ⚠2│  │ ◌ 오늘 1건               ⚠ 2 │
│               │  │ 치과 정기 검진      오늘 14:00 │
│ 치과 정기 검진 │  │ 장학금 서류 제출    내일 18:00 │
│ 오늘 14:00     │  │ 전기요금 확인           금요일 │
└───────────────┘  └───────────────────────────────┘
   소형 2×2              중형 4×2
```

### 크기가 커진다고 새 정보를 더하지 않는다

| 크기 | 무엇 |
| --- | --- |
| 소형 (2×2) | 다음 하나 · 지난 마감 배지 |
| 중형 (4×2) | 요약 줄 + 세 건 |
| 대형 (4×4) | 요약 줄 + 여섯 건 |
| 특대 (8×4, iPad) | 요약 줄 + 여덟 건을 **두 단**으로 |

같은 목록이 길어질 뿐이다. 작은 위젯에만 있는 정보를 두면 사용자는 크기를 바꿀
때마다 무언가를 잃고, 어느 크기를 골라야 하는지 매번 따져야 한다.

특대만 두 단으로 나눈다. 한 단으로 늘이면 오른쪽 절반이 통째로 빈다.

### 줄 수를 화면 높이에 맡기지 않는다

넘친 줄은 잘리는 것이 아니라 **밀려서 아예 안 보인다.** 그래서 크기마다 줄 수를
코드에 못 박는다 (`NextTaskView.rowLimit`).

### 날짜 문구는 만들지 않는다

`DueDateText` 에 폭 등급(`narrow`)만 넘긴다 (CLAUDE 규칙 15). 위젯은 이 제품에서
가장 좁은 자리라, 여기서 완전 서술형을 쓰면 반드시 잘린다.

## 2. 잠금화면 — 찍어서 담기

```
   ○         ┌──────────────────────┐
  ( ◌ )      │ ◌  찍어서 담기        │    ◌ 오늘 14:00 치과 검진
   ○         │    오늘 14:00 치과 검진│
  원형        └──────────────────────┘        인라인
                     사각형
```

### 표식은 맥 메뉴바 아이콘과 같다

같은 물방울 윤곽(`Bead`)을 쓴다. 그래서 `BeadShape.swift` 를 화면 폴더에서
`core/swift/Design/` 으로 옮겼다 — **이 제품의 표식은 하나**이고, 자리마다 다르게
그리면 같은 물건으로 보이지 않는다.

`AccessoryWidgetBackground()` 를 쓰지 않는다. 그건 시스템이 주는 **흐린 원판**인데,
물방울 뒤에 깔면 배경화면이 그 원만큼 뿌예져서 물방울이 유리에 맺힌 것이 아니라
**접시 위에 놓인 것**처럼 보인다. 이 제품의 표식은 뒤가 비쳐야 한다.

잠금화면 위젯은 메뉴바 아이콘과 같은 제약을 받는다. 시스템이 알파 채널만 보고
색을 스스로 칠하므로 **정할 수 있는 것은 실루엣뿐**이다. 그래서 광점을 파내지
않고 채운다 — 이 크기에서 파내면 선과 구멍 사이가 1pt 아래로 내려가 뭉갠다.

### 셋 다 만드는 이유

사용자가 잠금화면의 **어느 자리**를 비워 뒀는지 우리는 알 수 없다.
하나만 만들면 그 자리가 이미 찬 사람은 이 위젯을 쓸 수 없다.

| 원형 | 시계 아래. 표식만 — 글자를 넣으면 두 자밖에 안 들어간다. **뒤에 흐린 원판을 깔지 않는다** |
| 사각형 | 표식 + 다음 일정 한 줄 |
| 인라인 | 시계 위 한 줄. 시스템이 도형을 그리지 않으므로 글자만 |

### 누르면 카메라가 뜬다

```
잠금화면 위젯 → whenly://capture → 카메라 → 찍기 → 줄에 세움 → 등록 알림
```

**스크린샷이 존재하지 않는 것**을 담는 길이 지금까지 없었다. 종이 안내문,
화이트보드, 전광판, 병원 접수증. 찍고 → 앨범에 들어가고 → 공유하고 → 고르는
넷을 지나야 했다. 잠금화면에서 한 번 누르는 것으로 그 넷을 없앤다.

찍은 뒤 확인 화면을 두지 않는다. 잘못 찍었으면 다시 찍으면 되고, 등록된 것은
알림에서 눌러 고치거나 지울 수 있다.

**시뮬레이터에는 카메라가 없다.** 확인하지 않고 열면 빈 검은 화면이 뜨고 취소도
되지 않는다. `CameraCaptureSheet.isAvailable` 을 보고 못 쓰면 이유를 말하고
사진 고르기로 돌린다.

## 3. 위젯은 무엇을 읽는가

**파생 값을 따로 저장하지 않는다** (CLAUDE 규칙 14).

```
App Group/Whenly/tasks.json  ←  앱이 쓴다
                             ←  위젯이 읽는다  → DueGrouping.groups(...)
```

위젯 전용 요약 파일을 두면 할 일이 바뀔 때마다 두 곳을 맞춰야 하고, 반드시 한
곳이 뒤처진다 — 그러면 **홈 화면 위젯만 지난주 일정을 계속 보여준다.**

그래서 위젯도 같은 원장을 읽고, 묶고 정렬하는 것은 앱과 **같은 순수 함수**에 맡긴다.

### 계산은 확장 밖에 둔다

위젯 확장 타깃의 코드는 **테스트 번들에 들어가지 않는다.** 그래서 계산을
`core/swift/Models/WidgetSnapshot.swift` 로 빼고, 확장에는 타임라인을 넘기는
껍데기(`SnapshotProvider`)만 남겼다.

위젯은 이 제품에서 눈으로 확인하기 가장 어려운 화면이다 — 홈 화면에 올려 두고
몇 시간을 기다려야 잘못을 안다. 테스트가 닿지 않는 자리에 계산을 두면 안 된다.

### 언제 다시 그리나

시스템은 하루에 몇 번만 위젯을 깨워 준다. **분 단위로 조르지 않는다.**

| 언제 | 왜 |
| --- | --- |
| 가장 가까운 마감이 지나는 순간 | "1시간 뒤" 가 "지난 마감" 으로 바뀐다 |
| 자정 | 오늘이 어제가 된다 |
| 할 일이 바뀔 때 | 앱이 `WidgetCenter` 로 직접 깨운다 |

**과거 시각으로 다시 그리라고 하지 않는다.** 주면 시스템이 곧바로 깨우고, 깨어나
보면 여전히 과거라 또 깨운다 — 위젯이 배터리를 먹는 흔한 방식이다.
`WidgetSnapshotTests.testNeverAsksToRedrawInThePast` 가 이걸 막는다.

### 빈 것과 못 읽은 것을 다르게 말한다

같은 화면을 보여주면 App Group 설정이 잘못된 사용자가 "아직 할 일이 없구나" 로
읽고 영영 그 사실을 모른다. 그래서 읽기 실패를 `try?` 로 삼키지 않고
(CLAUDE 규칙 8) 이유를 `unavailableReason` 에 담아 화면까지 올린다.

## 4. 붙이는 데 필요한 설정

| 무엇 | 어디 | 어긋나면 |
| --- | --- | --- |
| App Group | `config/apple/WhenlyWidgets.entitlements` | 위젯이 언제나 "할 일을 읽지 못했어요" |
| URL 스킴 `whenly` | `project.yml` 의 `CFBundleURLTypes` | 위젯을 눌러도 **아무 일도 안 일어난다** (오류도 없다) |
| `NSCameraUsageDescription` | `project.yml` | 카메라를 여는 순간 앱이 죽는다 |

스킴이 어긋나는 사고는 실행해 보기 전까지 아무도 못 잡는다. 그래서
`DeepLinkTests.testSchemeMatchesTheOneRegisteredInTheBundle` 이 실제 번들의
`CFBundleURLTypes` 를 읽어 코드의 상수와 대조한다.

## 5. 확인한 것 · 못 한 것

| | 상태 |
| --- | --- |
| 위젯 확장이 앱에 심어지는가 | ✅ `PlugIns/WhenlyWidgets.appex` 확인 |
| URL 스킴이 등록됐는가 | ✅ 시뮬레이터가 `whenly://capture` 를 앱으로 보냄 |
| 스냅샷 계산 · 갱신 시각 | ✅ 단위 테스트 |
| 홈 화면에 올려 실제로 그려지는 모습 | ⬜ 시뮬레이터에서 위젯 배치를 자동화할 수 없다 |
| 잠금화면 위젯 → 카메라 → 등록 | ⬜ 시뮬레이터에 카메라가 없다. 실기기 필요 |

마지막 둘은 실기기 서명·App Group 프로비저닝과 함께 확인한다.
