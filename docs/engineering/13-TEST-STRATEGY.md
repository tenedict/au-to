## 3. 수동 시나리오 (자동이 못 보는 것)

| # | 시나리오 | 어디서 | 통과 조건 |

| M-1 | 공유 시트로 담기 → 앱에서 확인 | **실기기** | 시트에 항목이 보이고, 앱을 열면 확인 화면이 한 번 뜬다 |
| M-2 | 캘린더 권한 거절 후 저장 | 실기기·시뮬 | 할 일은 저장되고 "할 일은 저장했어요"가 뜬다 |

## 4. TDD 를 의무화하는 영역

아래는 **실패 테스트를 먼저 보고** 고친다. 예외 없다.

- 마감 묶음 분류와 정렬
- 알림 시각 계산과 식별자
- 초안 확인 필요 판정
- 저장·복원과 버전 이동
- 백엔드 요청 계약과 응답 검증
- 캡처 삭제 조건

**왜 이것들인가** — 전부 "화면에서는 맞아 보이는데 틀린" 부류다. 지난 마감이 하나
아래로 밀려 있어도, 알림이 한 시간 늦어도 눈으로는 모른다.

## 6. 테스트를 믿기 위한 규칙

1. **새 규칙은 일부러 어겨 보고 빨간불을 확인한 뒤 넣는다.** 안 잡히는 규칙은 초록불만 부풀린다
2. **`now` 는 언제나 인자다.** 안에서 읽으면 테스트가 오늘 날짜에 따라 흔들린다
3. **`--quick` 으로 본 초록은 iOS 계약을 검증하지 않았다.** 완료 판정에는 전체 실행이 필요하다
4. **버그는 재현 테스트 없이 고치지 않는다**
5. **확인 못 한 항목은 확인 못 했다고 적는다.** 수용 기준별로 ✅/⚠️ 를 나눈다
