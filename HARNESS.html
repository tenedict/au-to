02명령은 하나다

각자 다른 명령을 쓰면 "내 쪽에서는 됐는데"가 생긴다.

./scripts/verify.sh          # 규칙 + 포맷 + 린트 + 백엔드 + iOS 테스트
./scripts/verify.sh --quick  # iOS 테스트 제외 (몇 초) — pre-commit 용
누가언제무엇을
사람완료 보고 전verify.sh
Claudeverify 스킬verify.sh
lefthookpre-commit규칙 · 포맷 · 린트 · 백엔드
lefthookpre-pushverify.sh 전체
CI (ubuntu)모든 푸시·PR규칙 · 백엔드
CI (macOS)PR · 수동verify.sh 전체

설치 안 된 도구는 건너뛰되 무엇이 빠졌는지 알린다. 없다고 조용히 통과시키면 검증이 거짓말을 시작한다. SwiftLint 가 없으면 "건너뛴 검사"에 brew install swiftlint 가 찍힌다.

CI 는 비용을 나눠 설계했다. macOS 러너는 private 저장소에서 분당 10배로 계산되므로, ubuntu 에서 도는 규칙 검사와 백엔드 테스트는 모든 푸시에서, iOS 빌드·테스트는 PR 과 수동 실행에서만 돈다.

하네스를 세우자마자 줄줄이 나왔다. 전부 빌드와 테스트를 통과하던 상태였다.

경로 한 글자가 어긋나면 모든 grep 이 아무것도 못 찾고 검사기는 통과를 보고한다. 그래서 규칙 0 이 먼저 디렉터리 존재와 훑은 파일 수(15개 이상)를 확인하고, 계약을 실제로 지키는 핵심 테스트 9건이 사라지지 않았는지도 본다.

05규칙은 일부러 어겨 본 다음에만 규칙이다

Sprint 1 에서 이 절차 덕분에 가짜 규칙 하나를 잡았다.

규칙 10(기본 모델 검사)을 처음에는 접두사 매칭으로 썼다.

# 처음 — 통과해 버린다
grep -qE '^(gpt-4\.1|gpt-4o|gpt-5|o[1-9])'    ← "gpt-5.6-luna" 가 "gpt-5" 로 시작한다

# 고친 뒤 — 정확 일치
printf '%s\n' $KNOWN_MODELS | grep -qxF "$model"

실제로 gpt-5.6-luna 를 넣고 돌려 보니 종료 코드 0 이 나왔다. 잡아야 할 값을 그대로 통과시킨 것이다. 정확 일치 목록으로 바꾼 뒤에야 종료 코드 1 이 나왔고, 그때 규칙으로 인정했다.

안 잡히는 규칙은 있는 것이 없는 것보다 나쁘다. 검사기가 본다고 믿고 사람이 안 보게 되기 때문이다. 새 검사를 넣으면 그 자리에서 위반 사례를 만들어 넣고, 빨간불과 종료 코드 1 을 확인한 뒤에 커밋한다.

06규칙이 확인하지 못하는 것

규칙은 grep 이다. "어떤 글자가 어디 있는가"까지만 답할 수 있다.

무엇규칙이 보는 것규칙이 못 보는 것
App Group네 파일의 문자열이 같은가그 그룹이 개발자 계정에 등록됐는가 → 실기기
알림UNUserNotificationCenter 가 서비스 안에만 있는가실제로 울리는가 → 테스트 + 실기기
기본 모델목록에 있는 이름인가OpenAI 가 실제로 제공하는가 → 사람
저장 실패try? storage. 가 없는가화면까지 실제로 올라가는가 → 테스트

규칙 통과 ≠ 올바름. 규칙은 문법과 구조를 본다. 올바름은 테스트만 본다. 실기기에서만 드러나는 것은 사람만 본다.

그래서 --quick(iOS 테스트 제외)으로 본 초록은 iOS 계약을 하나도 검증하지 않았다.

왜 이것들을 순수 함수로 뺐나

전부 "화면에서는 맞아 보이는데 틀린" 부류다. 지난 마감이 하나 아래로 밀려 있어도, 알림이 한 시간 늦어도, 지갑 카드가 2pt 더 겹쳐도 눈으로는 모른다.

예를 들어 지갑 스택의 배치는 WalletStackLayout 순수 함수이고, 테스트가 마지막 카드가 잘리지 않는지까지 숫자로 확인한다. 뷰 안에 뒀으면 "아래가 조금 잘리네"를 매번 눈으로 잡아야 했을 것이다.

08커밋 기록에는 사람만 남는다

AI 도구가 붙이는 공동 작성자 트레일러는 저자 정보를 흐리고 기여자 목록에 사람이 아닌 항목을 만든다.

층무엇건너뛸 수 있나
.githooks/commit-msg조용히 지우고 통과시킨다--no-verify 로 가능
.github/workflows/commit-hygiene.yml남아 있으면 CI 실패불가

훅은 편의이고 CI 가 강제다. 이 구조는 하네스 전체에 반복된다 — 훅은 건너뛸 수 있으므로 최종 강제는 언제나 CI 가 한다.
