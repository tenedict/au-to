# macOS 앱

> 화면에 떠 있는 물방울에 스크린샷을 끌어다 놓으면 캘린더까지 간다.
> 2026-08-01 · 실제로 끝까지 돌려서 확인함

---

## 0. 왜 다르게 만들었나

같은 제품이지만 **쓰는 방식이 다르다.**

| | iOS | macOS |
| --- | --- | --- |
| 들어오는 길 | 공유 시트 · 사진 고르기 | **물방울에 끌어다 놓기** · 다른 앱으로 열기 · 파일 고르기 |
| 확인 | 확인 화면을 **반드시** 거친다 | 분명하면 **바로 넣고 되돌릴 수 있게** |
| 목록 | 지갑 스타일 겹침 스택 | 평범한 목록 |
| 상시 존재 | 앱을 연다 | 메뉴바 + 떠 있는 물방울 |

폰에서는 한 손으로 몇 번 탭하는 것이 자연스럽고, 맥에서는 **끌어다 놓는 것**이 자연스럽다.
화면이 넓고 포인터가 정확하니 겹쳐 쌓을 이유도 없다.

**공유하는 것과 안 하는 것**

```
공유한다   Models · Services · Store · Shared   (코드 수정 0)
안 한다    Views                                (화면은 플랫폼마다 다른 것이 맞다)
```

`VisionOCRService` 만 손봤다. `UIImage` 를 쓰고 있었는데 ImageIO 의 `CGImageSource` 로 바꿨다 —
`UIImage`/`NSImage` 는 플랫폼마다 다르지만 `CGImage` 는 어디서나 같다.

## 1. 물방울

```
        ╭────────╮
       │    ◌     │   창 72 × 72 · 물방울은 44pt (쉴 때)
        ╰────────╯
     화면 오른쪽 아래에 떠 있다
```

**유리에 맺힌 물방울이다.** 예전에는 스테인리스 고리였는데, 그건 물건이지 물이 아니었다.

### 모양 — 화면에서는 완전한 원, 메뉴바에서는 맺힌 윤곽

같은 물건인데 모양이 둘이다. **크기가 다르면 같은 모양도 다른 뜻이 되기 때문**이다.

| 자리 | 모양 | 왜 |
| --- | --- | --- |
| 떠 있는 물방울 (44pt) | 완전한 원 | 이 크기에서 비대칭은 성격이 아니라 **찌그러짐**으로 보인다 |
| 메뉴바 아이콘 (18pt) | 맺힌 윤곽 (`Bead`) | 이 크기에서 비대칭은 "손으로 그린 것"으로 읽혀 성격이 된다 |

`Bead.cgPath(in:)` 는 표면장력과 중력이 함께 만든 모양을 흉내 낸다 — 아래가 조금
넓고 평평하고, 위가 더 둥글고, 좌우가 완전히 대칭이 아니다. 아이콘에서는 그
어긋남이 도형과 물을 가르지만, 화면에 뜬 44pt 원에서는 실수처럼 보였다.

### 층이 넷이고 순서가 곧 광학이다

| 층 | 무엇 | 왜 |
| --- | --- | --- |
| 1 · 유리 | `.glassEffect(.clear)` (macOS 26+) | 굴절은 아니지만 "물이 고여 있다"가 생긴다. `.regular` 는 뒤를 서리처럼 가려 **불투명한 알약**이 된다 |
| 2 · 어두운 가장자리 | 가운데 투명 → 테두리로 갈수록 짙어짐 | **흰 배경 위에서 물방울을 보이게 하는 것은 이것 하나다.** 흰 림라이트만 쓰면 흰 화면에서 통째로 사라진다 |
| 3 · 얇은 밝은 선 | 안쪽 테두리 | 유리에 닿은 물의 경계 |
| 4 · 하이라이트 둘 | 왼쪽 위 작고 밝은 점 · 오른쪽 아래 넓고 옅은 반사 | 물방울이 물방울로 읽히는 것은 굴절이 아니라 이 둘 때문이다 |

macOS 26 미만에서는 1층을 그리지 않는다. 채울 방법이 흐림뿐인데, **흐린 판은
물방울이 아니라 서리다.** 대신 가운데가 완전히 투명해 뒤가 그대로 보인다.

> **진짜 굴절은 넣지 않았다.** 공개 API 로는 창 뒤를 굴절시킬 수 없고
> (`CALayer.backgroundFilters` 는 창 경계를 넘지 못하고, Liquid Glass 는 직선을
> 밀지 않는다), 직접 캡처하려면 화면 기록 권한이 필요하다. 68pt 장식 하나를 위해
> "이 앱이 화면 전체를 봅니다"를 승인받는 것은 **원본 이미지가 기기를 떠나지
> 않는다**고 말해 온 이 제품과 맞지 않는다. 실험과 판정은 개발 보고서 부록 A 에 있다.

### 상태는 크기로만 말한다

| 상태 | 지름 | 왜 |
| --- | --- | --- |
| 쉴 때 | 44pt | 떠 있는 것은 작을수록 화면을 덜 가린다 |
| 읽는 중 | 48pt | 회전자가 함께 돈다 |
| 누르는 중 · 옮기는 중 | 52pt | 손이 닿아 있다는 사실 하나. 누르다 그대로 끌 때 크기가 또 튀면 미끄러진 것처럼 보인다 |
| 끌고 오는 중 | 58pt | **겨냥하는 중에는 목표가 커져야 놓기 쉽다** |

**색을 아예 쓰지 않는다.** 강조색 고리와 물결이 있었지만 쇠에 파란 테가 겹치니
물건 하나가 아니라 **두 개**로 보였다. 색을 안 쓰니 규칙 13(색만으로 알리지 않기)도
저절로 지켜진다.

모션 줄이기는 **크기 변화가 아니라 애니메이션**을 끈다. 크기는 이 물방울의 유일한
상태 신호라, 없애면 무슨 일이 일어나는지 알 방법이 사라진다.

### 창은 고정이고 물방울만 커진다

크기 규칙은 화면이 아니라 `DropletAppearance`(순수 함수)에 있고 테스트가 지킨다.
값들이 **서로 묶여 있기** 때문이다 — 가장 커진 물방울이 창을 넘으면 가장자리가
잘리고, 잘린 물방울은 물방울로 보이지 않는다.

창은 72pt 로 고정이다. 창까지 같이 커지면 겨냥하는 중에 드롭 영역이 움직여서
커서가 안팎을 오간다. 풀리면 다시 커지고, 커지면 또 들어와 **깜빡임이 된다.**
그래서 눈에 보이는 물방울보다 **실제로 받는 영역이 넓다.**

### 옛 사고 — 그림자가 만든 네모

한때 창이 고리에 딱 맞는 68 × 68 이었다. 중심에서 모서리까지(48pt)가 고리
반지름(34pt)보다 가까워서, 그림자가 모서리에 닿고 창 경계에서 **직선으로 잘렸다.**
그 잘린 직선이 뿌연 네모로 보였다.

```
------*###*------------.......................------------####------   ← 모서리에 옅은 층
###+------.................................................------###   ← 가운데는 알파 0
```

> 눈으로는 "흐릿하다"까지만 보인다. 무엇이 흐린지는 **알파 채널을 찍어야** 알 수 있었다.

지금은 창(72)이 물방울(최대 58)보다 넉넉히 커서 그림자가 잘리지 않는다.
`NSHostingView` 의 배경을 비우는 것은 그대로 유지한다 — 창을 투명하게 해도
안쪽 뷰가 칠하면 소용없다.

### 누르기 · 옮기기 · 탭을 제스처 하나로

제스처를 나눠 달면 탭과 드래그가 서로를 먹는다. `DragGesture(minimumDistance: 0)`
하나로 셋을 다 받고, 문턱(3pt)을 넘으면 그때부터 창을 옮긴다.

**이동량은 제스처가 알려 주는 값을 쓰면 안 된다.** 그 값은 뷰의 좌표계에서 재는데
창을 옮기면 뷰도 함께 움직여서 이동량이 상쇄된다 — 실제로 그렇게 만들었다가
967pt 를 끌었는데 창은 483pt 만 움직였다. **정확히 절반이다.**

그래서 화면 좌표(`NSEvent.mouseLocation`)를 직접 읽어 잡은 지점과 창 원점의 간격을
유지한다. AppKit 의 창 끌기와 같은 방식이고 되먹임이 없다.

### 메뉴바 아이콘

같은 윤곽에 광점 하나. **메뉴바 아이콘은 템플릿 이미지다** — 시스템이 알파 채널만
보고 색을 스스로 칠한다(밝은 메뉴바에서 검정, 어두운 메뉴바에서 흰색, 눌리면 반전).
그래서 정할 수 있는 것은 **실루엣 하나뿐**이고 색·그라디언트·굴절은 들어가지 않는다.

`drop.fill` 을 쓰지 않는 이유는 그것이 **떨어지는** 물방울이라 꼬리가 있기 때문이다.
이 제품의 물방울은 유리에 맺힌 것이라 꼬리가 없다.

| 왜 이렇게 | |
| --- | --- |
| 광점을 파내지 않고 **채운다** | 18pt 에서 윤곽 안을 파내면 선과 구멍 사이가 1pt 아래로 내려가 뭉갠다 |
| 광점을 안쪽으로 `0.82` 당긴다 | 물방울에서는 흐릿한 덩어리라 가장자리에 걸쳐도 되지만, 여기서는 또렷한 점이라 윤곽선과 붙어 하나로 뭉친다 |
| `NSImage(size:flipped:drawingHandler:)` | `lockFocus` 로 그리면 그 순간의 배율로 굳는다. 배율이 다른 화면으로 옮기면 흐려진다 |

### 왜 `NSPanel` 인가

SwiftUI 의 `Window`/`WindowGroup` 으로는 이 조합을 만들 수 없다.

| `.nonactivatingPanel` | 물방울을 눌러도 **작업하던 앱이 뒤로 가지 않는다.** 그 앱에서 그대로 끌어와야 한다 |
| `.floating` | 다른 창 위에 떠 있는다 |
| `canJoinAllSpaces` | 데스크톱을 바꿔도 따라온다 |
| 투명 배경 | 원 밖의 사각형이 보이지 않는다 |

위치는 사용자가 옮기면 기억한다 (`setFrameAutosaveName`).

## 1.5 대시보드 — 사이드바와 캘린더

물방울을 누르거나 메뉴바에서 열면 나오는 창이다. 한때 목록 하나였고, 화면이
넓은데 마감 묶음을 한 번에 훑을 방법이 없어서 급한 것을 보려면 스크롤을 해야 했다.

```
┌──────────────┬──────────────────────────────┐
│ 할 일        │  지난 마감                    │
│  모든 할 일 11│  ⚠ 치과 정기 검진  7/31 14:00 │
│  지난 마감  3│  ⚠ 전기요금 자동이체 확인 8/1  │
│  오늘       1│  ⚠ 장학금 서류 제출 8/2 18:00  │
│  앞으로 7일 3│                               │
│  그 뒤      2│                               │
│  날짜 없음  2│                               │
│  완료       2│                               │
│              │                               │
│ 보기         │                               │
│  캘린더      │                               │
└──────────────┴──────────────────────────────┘
  공유 상자 상태 · 오류 · 분석 엔진
```

**iOS 의 지갑 스택을 옮기지 않았다.** 맥은 화면이 넓고 포인터가 정확해서, 겹쳐
쌓는 것보다 왼쪽에서 고르고 오른쪽에서 보는 쪽이 낫다. 화면은 플랫폼마다 다른
것이 맞다 — 대신 **무엇이 어느 묶음이고 어떤 순서인지는 옮기지 않는다.**

| | |
| --- | --- |
| 묶음과 순서 | `TaskScoping` (`core/swift/Models/TaskScope.swift`) — iOS 와 같은 함수 |
| 사이드바 숫자 | 같은 함수가 센다. 화면이 세면 "오늘 3건" 과 목록 길이가 언젠가 어긋난다 |
| 빈 묶음 | **감추지 않는다.** 일하는 동안 항목이 사라지면 누르려던 자리가 움직인다 |
| 지난 마감 | 색과 기호를 함께 쓴다 (규칙 13) |
| 상태 줄 | 담기 상태·오류·분석 엔진. 창 어디에 있든 같은 자리 |

홈 화면은 빈 묶음을 감추는데 사이드바는 감추지 않는다 — 같은 데이터를 다르게
다루는 것이 아니라, **목록과 내비게이션의 요구가 다르기 때문**이다.

### 캘린더

`MonthGridBuilder` 와 `tasksByDay()` 를 iOS 캘린더와 그대로 공유한다.
날짜 계산은 화면에 한 줄도 없다.

- 월 격자에 마감이 있는 날은 점(최대 3개), 오늘은 옅은 원, 고른 날은 채운 원
- 날짜를 누르면 아래에 그날의 일정 — 종일이 위, 시간 있는 것은 이른 시각부터
- **여기서는 고치지 않는다.** 원장은 앱 하나뿐이고 캘린더는 다른 각도일 뿐이다.
  머리글 오른쪽에 "보기만 해요 · 고치기는 왼쪽에서" 를 붙여 그 사실을 말한다
- 격자와 일정을 한 스크롤에 둔다. 따로 스크롤시키면 창을 줄였을 때 아래가
  조용히 잘리고, 잘린 줄에 그 안내가 들어 있으면 안내가 없는 것과 같아진다

### 눌러 보기

이 앱은 `LSUIElement` 라 Dock 아이콘이 없고 창을 여는 길이 메뉴바와 물방울
클릭뿐이다. 둘 다 사람 손이 필요해서, 화면 확인을 자동화할 수 없었다.

```bash
open -n --env CAPTURETASK_OPEN_LIST=1 <CaptureTask.app>   # DEBUG 빌드에서만
```

iOS 의 `CAPTURETASK_TAB` · `CAPTURETASK_SHEET` 와 같은 갈고리다.

## 2. 바로 넣기 — 그리고 되돌리기

**"AI 결과는 제안이다"(ADR-4)를 버리지 않았다.** 두 갈래로 나눴을 뿐이다.

```
분명할 때   바로 넣는다  →  "넣었어요 · 실행 취소 · 고치기" 배너 (8초)
모호할 때   확인 창을 연다
```

확인 화면은 **저장 전에** 사람을 세우고, 되돌리기는 **저장 후에** 결정권을 남긴다.
둘 다 사람이 최종 판단을 하고, 다른 것은 속도뿐이다.

> **그래서 실행 취소가 반드시 있어야 한다.** 없으면 그냥 조용한 자동 저장이 된다.

### 판정 — `AutoFilePolicy`

```
날짜 없음                  →  물어본다 ("날짜를 찾지 못했어요")
ambiguities 있음           →  물어본다 (그 모호점을 그대로 보여준다)
confidence < 0.80          →  물어본다
그 밖                      →  바로 넣는다
```

**`ambiguities` 를 `confidence` 보다 먼저 본다.** 실제 호출에서 confidence 가
0.9~1.0 으로만 나와 눈금 역할을 못 하기 때문이다([12장 §3](../engineering/12-IMPLEMENTATION-READINESS.md)).
지금 실제로 거르고 있는 것은 `ambiguities` 쪽이다.

### 되돌리기가 하는 일

할 일과 **캘린더 일정을 둘 다** 거둔다. 하나만 지우면 사용자는
"취소했는데 일정이 그대로"인 상태를 보게 된다.

## 3. 들어오는 길 네 가지

| 길 | 되나 | 비고 |
| --- | --- | --- |
| 물방울에 끌어다 놓기 | ✅ | 주 경로 |
| 파인더 "다른 앱으로 열기" | ✅ | 실제로 끝까지 확인함 |
| 앱 아이콘에 끌어다 놓기 | ✅ | 같은 경로 (`CFBundleDocumentTypes`) |
| 메뉴바 → 파일에서 고르기 | ✅ | 끌어다 놓기를 모르는 사용자용 |
| **공유 메뉴** | 🟡 | 파일 URL 로 오는 공유만. 아래 참고 |

### 공유 확장의 제약

확장은 **파일 URL 만 받는다.** 그래서 App Group 이 필요 없다.

`NSWorkspace.open(url)` 로 앱을 열면 LaunchServices 가 **앱에게 그 파일의 샌드박스
확장을 준다** — "다른 앱으로 열기"와 정확히 같은 길이다. 확장이 파일을 복사할 필요가 없고,
따라서 앱과 확장이 공유하는 저장소도 필요 없다.

이미지 **데이터**로 오는 공유(예: 사파리에서 이미지 복사)는 받지 않는다.
그건 확장이 어딘가에 써 두고 앱이 읽어야 하는데, macOS 의 App Group 은
**팀 식별자 접두사를 요구한다** — iOS 의 S-1.3 과 같은 제약이다.

## 4. 샌드박스

| entitlement | 왜 |
| --- | --- |

**샌드박스가 실제로 막는 것을 확인했다.** 검증하려고 `CAPTURETASK_FILE` 로 임의 경로를

아니기 때문이다 — 정상 동작이다. 실제 드롭과 파일 고르기는 샌드박스 확장을 함께 받는다.

> `~/Library/Containers/com.example.capturetask.mac/Data/Documents/`

## 6.5 앱 아이콘

물방울 안으로 할 일 세 개가 사방에서 빨려 들어간다 — 이 제품이 하는 일 그대로다.
흩어져 있던 것(스크린샷)이 한 곳으로 모여 정리된다.

```bash
swift scripts/icon/MakeIcon.swift <출력폴더>
```

손으로 그리지 않고 스크립트로 짓는 이유 — 색이나 각도를 고칠 때 모든 크기를 다시
만들어야 하는데, 손으로 하면 어느 크기 하나가 반드시 옛것으로 남는다.

**막대를 물방울보다 먼저 그린다.** 밖에서 안으로 가로지르게 하고 그 위에 반투명한
유리를 덮으면 안쪽 부분이 물속에 잠긴 것처럼 보인다 — 그게 "들어간다"는 그림이다.
유리 안에 가둬 그리면 그냥 무늬가 된다.

**유리는 파랑이 아니라 흰색 계열이다.** 파란 유리를 씌웠더니 노란 막대가
올리브색으로 죽었다 — 보색이 상쇄된다.

### 겪은 함정 — 요청한 것의 두 배가 나온다

`NSImage.lockFocus()` 는 Retina 화면의 배율(2x)을 적용한다. 1024를 요청했는데
2048이 나왔고 Xcode 가 아이콘을 거부했다. `rep.size` 를 고쳐도 픽셀 수는 그대로다.

`CGContext` 를 직접 만들어 픽셀 수를 못 박았다. `noneSkipLast` 로 **알파 없는**
비트맵을 만드는 것도 함께 해결된다 — iOS 앱 아이콘은 투명도를 가질 수 없는데,
`NSBitmapImageRep` 는 알파 없는 그리기 문맥을 만들지 못한다.

생성기가 요청 크기와 다르면 **그대로 내보내지 않고 멈춘다.** 한 번 이걸로 거부됐다.
