## Sprint 1 회고 (2026-08-01)

### 무슨 일이 있었나

검증 하네스를 세우자마자, **문서에는 있고 코드에는 없던 것**이 열 건 나왔다.
전부 빌드와 테스트를 통과하던 상태였다.

가장 컸던 것은 App Group 이었다. `Config/CaptureTask.entitlements` 와
`CaptureTaskShare.entitlements` 가 둘 다 빈 `<dict/>` 였다.
그래서 `containerURL(forSecurityApplicationGroupIdentifier:)` 이 언제나 nil 을 돌려주고,
공유 시트로 담은 스크린샷은 앱에 **영원히** 도착하지 않았다.

> 이 결함의 성질이 나쁘다. **담기는 성공한다.** 사용자에게는 "담았어요" 라고 말한 뒤
> 아무 일도 일어나지 않는다. 어디가 고장인지 짐작할 단서가 하나도 없다.

고치려고 entitlements 파일에 직접 써 넣었더니, `xcodegen generate` 한 번에 다시
빈 `<dict/>` 가 됐다. XcodeGen 은 `entitlements.properties` 가 없으면 파일을 덮어쓴다.
**고쳤다고 믿고 넘어갈 수 있었던 자리다.**

## 규칙으로 승격한 것

### 1. 생성물에 손으로 고친 것은 고친 것이 아니다

**사건** — entitlements 파일에 App Group 을 써 넣었지만 다음 generate 에서 사라졌다.

**규칙** — 생성되는 파일을 고쳐야 할 때는 **원본을 찾아 고치고, 다시 생성해서 확인한다.**
`.xcodeproj` 를 추적에서 뺀 것도 같은 이유다 (ADR).

**강제** — 프로젝트 규칙 1이 `project.yml` 에 `com.apple.security.application-groups` 가
있는지까지 확인한다. 파일만 맞고 원본이 비어 있으면 잡힌다.

### 2. 규칙은 일부러 어겨 보고 빨간불을 본 다음에만 규칙이다

**사건** — 기본 모델 검사를 접두사 매칭(`^gpt-5`)으로 썼다.
가짜 이름 `gpt-5.6-luna` 를 넣어 보니 **그대로 통과했다.**

**규칙** — 새 검사를 넣으면 그 자리에서 위반 사례를 만들어 넣고, 빨간불과
종료 코드 1을 확인한 뒤에 커밋한다.

**왜** — 안 잡히는 규칙은 초록불만 부풀린다. 있는 것이 없는 것보다 나쁘다 —
검사기가 본다고 믿고 사람이 안 보게 되기 때문이다.

### 3. "실재하는가"를 검사기가 대신 확인할 수 없을 때는 목록으로 만든다

**사건** — OpenAI 모델 이름이 실재하는지 검사기는 알 수 없다.

**규칙** — 검사기가 판정할 수 없는 것은 **저장소 안의 목록**과 정확 일치로 본다.
새 값을 쓰려면 사람이 목록에 한 줄 더하며 한 번 확인하게 된다.

**적용** — `scripts/check-project-rules.sh` 의 `KNOWN_MODELS`.

### 4. 조용한 대체(fallback)를 만들지 않는다

**사건** — 백엔드가 죽었을 때 규칙 기반 분석기로 자동 전환하려다 멈췄다.

**규칙** — 품질이 낮은 경로로 **자동으로** 떨어지지 않는다.
사용자는 AI 가 나빠졌다고 생각하고, 우리는 백엔드가 죽은 줄 모른다.
대체 구현은 **명시적으로 골랐을 때만** 쓴다 (`CAPTURETASK_OFFLINE=1`).

**같은 원리** — `verify.sh` 는 도구가 없으면 조용히 통과시키지 않고 무엇이 빠졌는지 적는다.

### 5. 메모리에만 있는 상태는 비용이 된다

**사건** — 확인 대기 초안이 메모리에만 있었다. 앱을 껐다 켜면 같은 캡처로
OCR 과 OpenAI 를 다시 불렀다.

**규칙** — 외부 호출의 결과는 영속화한다. 특히 **돈이 드는 호출**은.

**적용** — `drafts.json` 영속화 + 캡처에 OCR 결과 캐시.

### 6. 저장 형식의 정밀도를 계약으로 적는다

**사건** — 저장 왕복 테스트가 실패했다. 값은 같아 보이는데 같지 않았다 —
ISO 8601 기본 포맷이 초 미만을 버린다.

**규칙** — 저장 형식이 잃는 정밀도를 **문서와 테스트에 명시**한다.
"대충 같으면 된다"로 넘기면, 같은 초에 만든 두 항목의 순서가 재실행 뒤에 뒤집히고
아무도 원인을 찾지 못한다.

**적용** — 밀리초까지 쓰고, `testDatesKeepMillisecondPrecision` 이 파일 내용까지 확인한다.

### 7. 눈으로 "대충 맞아 보이는" 것일수록 순수 함수로 뺀다

**사건** — 지갑 스택의 겹침·밀림 계산.

**규칙** — 배치·정렬·시각처럼 **틀려도 그럴듯해 보이는** 계산은 뷰에서 빼서
순수 함수로 만들고 숫자로 잡는다.

**적용** — `WalletStackLayout`(7건) · `DueGrouping`(13건) · `ReminderSchedule`(10건) ·
`MonthGrid`(9건). 전부 밀리초 안에 돈다.

## 잘한 것

- **하네스를 먼저 세운 것.** 기능부터 만들었으면 열 건을 못 찾았다
- **규칙마다 근거를 옆에 적은 것.** `CLAUDE 규칙 7`, `ADR-1` 이 지적 옆에 붙어 있어
  "왜 이게 막히는지"를 되묻지 않아도 된다
- **검사기가 자기 자신을 검사하는 것 (규칙 0).** 경로가 어긋나면 모든 grep 이
  빈손으로 돌아와 조용히 초록이 난다. 훑은 파일 수와 핵심 테스트 존재를 먼저 확인한다

## 아쉬운 것

- **화면 테스트가 없다.** 지갑 스택의 배치는 계산으로 잡았지만, 실제로 겹쳐 보이는지는
  여전히 눈으로만 확인한다
- **실제 OpenAI 응답을 한 번도 못 봤다.** 백엔드 테스트 15건이 전부 대역이다.
  `parseTaskDraftResponse` 의 가정이 맞는지는 키를 넣어 봐야 안다 (B-2)
- **접근성을 나중으로 미뤘다.** 카드 높이를 고정값으로 둔 대가가 R2 게이트를 막고 있다
