# Engineering Playbook

`travel_together`에서 효과가 검증된 BMAD + Superpowers 규율을 가져왔다.

## 두 층

```text
Brief → PRD → SPEC → Architecture → Stories → Readiness → Sprint
                                      ↓
브레인스토밍 → 작은 계획 → RED/GREEN/REFACTOR → 검증 → 리뷰
```

## 계획

한 태스크는 2~5분, 파일/함수/검증 방법을 적는다. 큰 제목 하나로 여러 쓰기 경로를
숨기지 않는다.

## TDD

날짜 파싱, 신뢰도, 중복, 상태 전이, inbox 삭제 조건은 실패 테스트를 먼저 보고 고친다.
버그는 재현 테스트 없이 수정하지 않는다.

## 디버깅

30분 이상 막히면 찍어보기를 멈춘다.

1. 최소 경로 재현
2. 범위를 절반씩 좁힘
3. 메커니즘 수준의 근본 원인
4. 재현 테스트와 전체 스위트로 증명

## 완료 정의

- 수용 기준을 항목별로 확인
- 새 테스트의 RED 확인
- 전체 테스트 초록
- 빌드 경고 0
- UI는 시뮬레이터와 필요한 경우 실제 기기에서 직접 조작
- 문서와 코드 일치

## 리뷰 순서

1. 명세 준수: 캡처가 유실되지 않는가, 낮은 신뢰도가 캘린더에 쓰이지 않는가
2. 코드 품질: 의존 방향, 중복, 이름, 접근성, 프라이버시

## 커밋

Conventional Commits(`feat`, `fix`, `test`, `docs`, `refactor`, `chore`)를 사용한다.
한 커밋에는 하나의 검토 가능한 관심사만 담고, 관련 테스트가 초록일 때 커밋한다.
