## 3. R1 — CONCERNS

### 막고 있는 것

| # | 항목 | 왜 막는가 |
| --- | --- | --- |
| B-1 | Bundle ID · App Group 프로비저닝 (D-1) | 공유 시트 경로가 실기기에서 확인되지 않는다 |
| B-2 | 실제 OpenAI 키로 E2E 1회 | 요청 계약은 테스트했지만 **실제 응답**을 본 적이 없다 |
| B-3 | M-1 ~ M-5 수동 시나리오 | 자동으로 볼 수 없는 경로 |

### B-2 를 특별히 적는 이유

백엔드 테스트 15건은 전부 `fetchImpl` 을 대역으로 바꿔 돈다. **실제 OpenAI 응답의
모양을 확인한 적이 없다.** `parseTaskDraftResponse` 가 `output[].content[].type === "output_text"`
를 가정하는데, 그 가정이 맞는지는 한 번 불러 봐야 안다.

> 사용자가 넣을 것은 `backend/.env` 의 `OPENAI_API_KEY` 한 줄뿐이다.
> 나머지는 전부 채워져 있다.

### 막지 않는 것

| 항목 | 왜 괜찮은가 |
| --- | --- |
| 중복 감지 (S-4.9) | 없어도 사용자가 지울 수 있다. 정책(D-5)이 먼저다 |
| 검색·필터 (S-4.10) | 할 일 개수가 적은 초기에는 스택으로 충분하다 |
| 캘린더 역동기화 | MVP 범위 밖 (ADR-7) |

## 4. R2 — FAIL

| # | 항목 | 근거 |
| --- | --- | --- |
| F-1 | Dynamic Type `.xxxLarge` 에서 카드가 잘린다 | NFR-A11Y-06 · G-2 · S-9.1 |
| F-2 | 모션 줄이기 미대응 | NFR-A11Y-07 · G-3 · S-9.2 |
| F-3 | 대비 높이기 미대응 | NFR-A11Y-08 · S-9.3 |
| F-4 | 백엔드 인증·rate limit 없음 | NFR-SEC-05 |
| F-5 | 평가셋 50건 없음 | S-2.3 · R-19 · R-20 위험이 무방비 |

**F-1 은 지갑 스택의 구조적 대가다.** 겹침 계산을 순수 함수로 유지하려고 카드 높이를
고정값으로 뒀다. 해소안(`@ScaledMetric` 으로 세 값을 함께 키우기)은 비율만 지키면
계약이 그대로라서 안전하다 — 다만 아직 안 했다.

**F-4 없이는 배포할 수 없다.** 지금 백엔드는 주소를 아는 누구나 우리 키로 요청을
보낼 수 있다. 로컬 전용이라 문제가 없을 뿐이다.

## 5. 판정 근거의 신뢰도

| 무엇이 | 얼마나 믿을 만한가 |
| --- | --- |
| 순수 계산 39건 | **높음.** 결정적이고 `now` 를 주입받는다 |
| 저장 계약 8건 | **높음.** 실제 파일로 돈다 |
| 유스케이스 13건 | **중간.** `SharedInbox` 경로는 대역이 아니라 우회했다 |
| 백엔드 15건 | **중간.** 실제 OpenAI 응답을 본 적이 없다 (B-2) |
| 정적 규칙 11건 | **중간.** grep 이라 "글자가 있는가"까지만 본다 |
| 화면 | **낮음.** 시뮬레이터 수동 확인뿐. UI 테스트가 없다 |

**규칙 통과 ≠ 올바름.** 이 표를 적는 이유는, 초록불 하나로 전부를 보증하는 착각을 막기 위해서다.
