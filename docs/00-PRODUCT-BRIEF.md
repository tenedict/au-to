# Product Brief

> BMAD Phase 1 · `bmad-product-brief`.

---

## 문제

메신저, 예약 화면, 공지, SNS에서 "나중에 해야 할 것"을 스크린샷으로 남기지만
사진첩에 묻힌다. 사용자는 다시 읽고, 날짜를 찾고, 할 일과 캘린더에 중복 입력한다.

그리고 **대개는 그 세 단계를 하지 않는다.** 스크린샷은 남겼다는 안도감만 주고,
마감은 그대로 지나간다.

---

## 약속

> "스크린샷을 한 번 공유하면 해야 할 일이 정리되고, 마감이 다가오면 알려 준다."

---

## 핵심 사용자

예약·공지·업무 요청·행사 정보를 스크린샷으로 자주 저장하는 iPhone 사용자.

전형적인 하루: 병원 예약 확정 문자, 관리비 고지, 행사 안내, 회의 시간 변경 —
전부 화면에 있고, 전부 나중에 해야 하고, 전부 사진첩에 쌓인다.

---

## 차별점

| | |
| --- | --- |
| **실행 가능한 할 일로 바꾼다** | 범용 노트 앱이 아니다. 제목과 마감이 있는 한 줄이 결과다 |
| **마감이 급한 순으로 보여준다** | 지갑처럼 쌓인 카드에서 지난 마감이 맨 위에 있다 |
| **놓치기 전에 알려 준다** | 로컬 알림 3종. 서버가 사용자의 할 일을 알 필요가 없다 |
| **소유권을 분리한다** | 앱 할 일이 원장, Apple 캘린더는 선택적 출력 |
| **로컬 우선, 확인 우선** | OCR 은 기기에서. AI 결과는 사람이 확인한 뒤에만 저장된다 |

---

## 하지 않기로 한 것

| | 왜 |
| --- | --- |
| AI 가 확인 없이 자동 저장 | 일정 오인식 하나가 앱 전체의 신뢰를 없앤다 |
| 캘린더 양방향 동기화 | "어느 쪽이 진짜인가"를 사용자도 코드도 답할 수 없게 된다 |
| 원본 이미지를 서버로 전송 | 스크린샷에는 대화·주소·예약 정보가 그대로 있다 |
| 서버 푸시 알림 | 서버가 사용자의 할 일과 마감을 알아야 한다 |
| 앱 안의 완전한 캘린더 앱 | Apple 캘린더가 이미 있다. 앱을 나가지 않을 정도만 |

---

## 북극성 지표

| 지표 | 목표 |
| --- | --- |
| 공유 시작 → 확인 완료 중앙값 | **15초 이내** |
| 제안된 날짜·제목을 **수정하지 않고** 저장한 비율 | **80% 이상** |
| 담은 캡처의 유실률 | **0%** |
| 마감 전 알림을 받고 완료한 비율 | 측정 예정 |

첫 두 지표가 이 제품의 존재 이유다. 15초를 넘거나 매번 고쳐야 한다면,
사용자는 그냥 직접 입력하는 편이 빠르다.

---

## 성공했을 때의 모습

사용자가 예약 문자를 받는다. 스크린샷을 찍고 공유 시트에서 한 번 누른다.
그 뒤로는 아무것도 하지 않는다.

하루 전 저녁 8시에 알림이 온다. 당일 한 시간 전에 한 번 더 온다.
앱을 열면 그 할 일이 맨 위에 있다.

**사진첩을 다시 뒤지는 일이 없다.**
