조사 개요

1.1 배경

Whenly 는 iOS 홈 화면에 지갑형 마감 적층을, macOS 에 사이드바 대시보드를 채택했다. 두 결정 모두 Apple 기본 앱의 패턴을 참고한 것이나, 실제 구현과 대조한 기록이 없다. 또한 개발 보고서 §9.1 에서 홈 화면 카드의 마감 표시가 다음 카드에 가려지는 결함이 확인되었으며, 해법을 정하려면 Apple 이 동일 문제를 어떻게 처리하는가를 먼저 확인해야 한다.

2.2 캡처하지 않은 것과 그 이유

개인 정보

일기와 macOS 미리 알림은 시뮬레이터에 존재하지 않아 사용자 본인의 계정 데이터가 담긴 실제 앱으로만 확인할 수 있었다. 일기 앱을 열었을 때 개인적인 기록이 표시되었으므로, 해당 캡처는 즉시 삭제하고 본 보고서에 포함하지 않았다. 두 앱에 대한 기술은 화면 구조와 타이포그래피에 한정하며, 기록의 내용은 어떤 형태로도 인용하지 않는다.

확보하지 못한 자료사유
지갑의 적층 카드 실물패스는 서명이 필요하여 시뮬레이터에 추가할 수 없다. 빈 상태의 안내 일러스트로 카드 형태만 확인했다
캘린더 월 격자권한 대화상자가 반복 표시되어 뷰 전환에 실패했다. 일 뷰 상단만 확보했다
알림 적층 (잠금 화면)시뮬레이터에서 알림 권한이 없어 표시되지 않았다
미리 알림의 한국어 장문 항목시뮬레이터 텍스트 입력이 실패했다. 행 구성은 확보한 항목으로 계측했다

2.3 근거의 등급

본 보고서의 기술은 근거를 세 등급으로 구분한다. 등급이 표시되지 않은 기술은 모두 [실측]이다.

등급의미
[실측]직접 실행하여 캡처하고 화면에서 계측한 것
[관찰]직접 실행하여 확인했으나 캡처를 남기지 않은 것 (§2.2)
[문헌]Apple Human Interface Guidelines 등 공개 문서에 근거한 것

계측값은 iPhone 17 Pro 기준 포인트(pt)이며, 3배 스크린샷에서 산출한 근사치다. 오차는 ±1pt 수준으로 본다.

3

지갑 (Wallet)

3.1 화면 구조

요소구성
타이틀좌측 상단 대형 타이틀 “지갑”. 스크롤 시 축소되는 iOS 표준 대형 타이틀
툴바우측 상단. 추가(+)는 단독 캡슐, 검색·더보기는 하나의 캡슐로 묶임
본문카드 1장. 상단 일러스트 영역과 하단 정보 영역의 2분할
동작카드 하단 우측에 “받기” 버튼. 설명과 같은 줄에 배치

주목할 점은 추가 동작만 별도 캡슐로 분리한 것이다. 세 버튼을 하나의 캡슐에 넣지 않고 가장 중요한 동작을 시각적으로 떼어 냈다. 캡슐 그룹은 iOS 26 에서 확대된 패턴으로, 관련 동작을 하나의 배경 위에 묶어 툴바의 시각적 밀도를 낮춘다.

3.2 카드 구성

속성계측 · 관찰
모서리 반경약 20pt. 화면 좌우 여백은 약 20pt
2분할상단 일러스트(약 160pt) / 하단 정보(약 70pt). 경계선 없이 배경 명도로만 구분
정보 영역제목(굵게) · 설명(2행까지) · 우측 버튼. 설명이 2행이 되어도 버튼은 수직 중앙을 유지
색카드 자체는 무채색. 색은 일러스트 안의 패스 종류(음악·커피·영화·항공·기프트·학위)에만 사용

3.3 적층 카드에 대한 확인 [문헌]

지갑의 핵심 인터페이스인 적층 카드는 패스가 있어야 표시되므로 본 조사에서 실물을 확인하지 못했다. 다만 빈 상태의 일러스트와 공개 문서로 다음을 확인할 수 있다.

특성내용
적층 대상고정 비율의 카드 이미지. 각 패스는 발급자가 정의한 고정 레이아웃을 가진다
노출 높이카드 상단의 고정 영역. 그 영역에 무엇을 넣을지는 발급자가 설계 시 결정한다
가변 텍스트패스 상단 노출 영역에 가변 길이 텍스트를 배치하는 구조가 아니다. 필드 수와 위치가 규격으로 고정된다

지갑이 적층할 수 있는 이유는 적층되는 대상이 높이가 고정된 카드이기 때문이다. 이 사실이 §9 의 결함 분석에서 결정적으로 작용한다.

미리 알림 (Reminders)

4.1 생성 흐름 — 모달을 쓰지 않는다

새 항목을 만들 때 미리 알림은 화면을 전환하지 않는다. 목록의 마지막에 행이 하나 추가되고 그 자리에 커서가 놓인다. 제목을 입력한 뒤 Return 을 누르면 다음 행이 이어 생성된다. 부가 속성(날짜·위치·깃발·첨부)은 키보드 위 4개 아이콘으로 제공되며, 필요한 사람만 누른다.

설계 결정효과
모달 없음연속 입력 시 화면 전환 비용이 0 이다
제목만 필수날짜는 선택. 날짜 없는 항목이 1급 시민이다
속성은 도구 모음입력 흐름을 끊지 않고 곁가지로 붙인다
우측 상단 완료 버튼채워진 원형 버튼 1개. 취소는 좌측 상단 <

4.2 목록 행 구성

속성계측
행 간격약 38pt (1행 항목 기준)
체크 원지름 약 22pt · 좌측 여백 약 16pt
제목 좌측 정렬체크 원 우측 약 20pt
구분선없음. 행 사이는 여백으로만 구분
보조 정보제목 아래 1행. 마감이 지난 경우 적색

4.3 마감 표시 방식 [관찰]

macOS 미리 알림에서 마감이 지난 항목은 제목 아래 1행의 적색 텍스트로 표시되며, 형식은 7/24/26, 17:48 과 같이 축약형이다. “2026년 7월 24일 오후 5시 48분” 같은 완전 서술형을 쓰지 않는다.

관찰
Apple 은 목록 행에서 날짜를 축약한다

행의 보조 정보는 1행에 들어가는 것이 전제다. 날짜 형식을 짧게 유지하는 것으로 그 전제를 지킨다. 행 높이를 늘려 긴 문자열을 수용하는 방식이 아니다.

4.4 색의 역할

색담당하는 정보색 없이도 전달되는가
적색마감 경과날짜 자체가 과거이므로 문자로도 판별 가능
청색목록 이름 · 조작 가능한 요소위치와 형태로 판별 가능
목록별 색목록 구분목록 이름이 함께 표시된다

온보딩 화면의 아이콘에는 녹색·주황·황색·청색이 사용되나, 기능 화면에서는 청색과 적색 두 가지로 수렴한다. 색은 장식이 아니라 상태와 조작 가능성만 담당한다.

캘린더 (Calendar)

5.1 화면 구조

영역구성기능
툴바좌측 < 8월 · 우측 캡슐(뷰 전환 · 검색 · 추가)좌측은 상위 뷰로, 우측은 조작
주 스트립요일 머리글 + 날짜 7개. 오늘은 적색 사각 배경주 단위 이동 · 현재 위치 표시
날짜 머리글“2026년 8월 2일 일요일” 중앙 정렬현재 보고 있는 날의 완전 서술
시간 격자정시마다 가로선 + 좌측 시각 라벨일정의 시간적 위치
현재 시각적색 가로선 + 좌측 적색 시각 알약지금이 어디인지
하단 바좌측 “오늘” 캡슐 · 우측 캡슐(월 뷰 · 받은 편지함)복귀와 전환

5.2 날짜 표기의 이중 기준

같은 화면 안에서 날짜를 두 가지로 표기한다.

위치표기이유
주 스트립2 — 숫자만7칸에 균등 배치해야 한다. 맥락은 상단 8월 이 제공
날짜 머리글2026년 8월 2일 일요일 — 완전 서술공간이 한 줄 전체이고, 모호함이 없어야 한다
현재 시각 알약23:11 — 시각만좁은 폭. 날짜는 이미 머리글에 있다

Apple 은 날짜 형식을 앱 단위로 고정하지 않고 배치할 공간의 폭에 맞춰 선택한다. 좁은 자리에는 짧은 형식을, 한 줄을 다 쓰는 자리에는 완전 서술을 쓴다.

5.3 오늘의 표현

맥락표현
주 스트립의 오늘적색 사각형(모서리 둥근) 배경 + 흰 숫자
현재 시각적색 선 + 적색 알약. 시간축 위의 위치를 함께 표시
복귀 수단하단 좌측 “오늘” 버튼. 항상 같은 자리

적색은 캘린더에서 “지금” 하나만 담당한다. 일정의 종류나 중요도에는 쓰이지 않는다. 미리 알림에서 적색이 “지났음”을 담당하는 것과 대비된다 — 같은 색이 앱마다 다른 하나의 의미를 맡는다.

6

일기 (Journal)

본 절에 화면 캡처가 없는 이유

일기 앱은 시뮬레이터에 포함되지 않아 사용자 본인의 실제 기록으로만 확인할 수 있었다. 개인적인 내용이 표시되어 캡처를 즉시 삭제했으며, 본 절은 [관찰] 등급의 구조 기술로만 구성한다. 기록의 내용은 인용하지 않는다.

6.1 화면 구조 [관찰]

영역구성
사이드바 상단정보 타일 2개 — “Insights”(연속 기록 주수 · 올해 항목 수 · 기록한 일수), “Places”(지도 축소판). 색 배경의 카드
사이드바 목록“Journals” 머리글 아래 저널 목록. 각 행은 색 아이콘 + 이름 + 우측 항목 수
본문 머리글“All Entries” 대형 타이틀
본문 구획월 단위 소제목(“July”)으로 항목을 묶는다
항목 카드흰 배경 · 모서리 둥근 카드. 본문 텍스트 + 하단에 아이콘 + 날짜 + 우측 ⋯
툴바사이드바 토글 · 추가(+) · 검색 필드

6.2 가변 길이 콘텐츠의 처리 [관찰]

일기는 본 조사에서 가장 중요한 사례다. 항목의 길이가 사용자마다, 항목마다 크게 다르기 때문이다. Apple 의 처리는 다음과 같았다.

관찰내용
카드 높이 상한카드에 최대 높이가 있다. 본문이 그보다 길면 아래쪽에서 잘리고 흐려진다
잘림의 표현단순 절단이 아니라 마지막 줄이 흐려지며 사라진다. “더 있다”가 시각적으로 전달된다
날짜의 위치카드 하단에 고정. 본문 길이와 무관하게 항상 보인다
카드 간 간격카드 사이에 명확한 여백. 겹치지 않는다
제목의 부재제목이 없는 항목은 본문 첫 줄이 그 역할을 한다. 별도 제목 행을 강제하지 않는다
핵심 관찰
가변 길이를 다루는 방법은 “겹치기”가 아니라 “잘라내고 알리기”다

일기는 카드를 겹치지 않는다. 대신 각 카드에 높이 상한을 두고, 넘치는 본문은 흐림으로 잘라낸다. 그리고 반드시 보여야 하는 정보(날짜)는 잘리는 영역 바깥인 카드 하단에 고정한다. 잘려도 잃는 것이 없도록 배치한 것이다.

6.3 사이드바의 정보 타일 [관찰]

일기의 사이드바 최상단에는 목록이 아니라 요약 타일이 온다. 연속 기록 주수와 항목 수를 큰 숫자로 보여 준다. 목록으로 들어가기 전에 “지금 상태”를 먼저 말하는 구성이다.

9.1 현상

iOS 홈 화면의 지갑형 적층에서 “치과 정기 검진” 카드의 마감 표시 2026년 7월 31일 14:00 이 2행으로 확장되어 두 번째 행이 다음 카드에 가려진다. 접근성 글자 크기에서는 적층을 해제해 해소했으나, 기본 크기에서도 문자열이 길면 재현된다.

9.2 원인 구조

적층은 “접힌 카드는 상단 일부만 보인다”를 전제한다. 그 노출 높이 (peekHeight)는 고정값이고, 그 안에 들어가야 하는 내용은 가변이다. 전제가 깨지는 조건은 두 가지다.

노출 높이  =  고정
표시 내용  =  제목 1행 + 마감 1행     ← 전제
실제       =  제목 1행 + 마감 2행     ← 문자열이 길 때
