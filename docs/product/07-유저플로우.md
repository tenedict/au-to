## 1. 주 플로우 — 스크린샷 한 장이 할 일이 되기까지

```
사진 앱 / 메신저
  │ 스크린샷을 공유 시트로
  ▼
┌─────────────────────┐
│ Share Extension      │  ← 별도 프로세스. 여기서 하는 일은 담기뿐
│ "담는 중이에요…"      │
└─────────┬───────────┘
          │ 이미지 + 메타데이터를 원자적으로 쓴다
          │ + 확인 요청 알림 (분석은 앱에서만 돌기 때문)
          ▼
   App Group 상자 ─────────────────────────┐
          │                                │
          │ 사용자가 앱을 연다              │ (안 열면 1시간 뒤 한 번 더 알린다)
          ▼                                │
┌─────────────────────┐                    │
│ RootView.refresh()   │                    │
│ scenePhase → active  │                    │
└─────────┬───────────┘                    │
          ▼                                │
   이미 할 일이 됐나? ──── 예 ──→ 상자에서 치움 ─┘
          │ 아니오
          ▼
   확인 대기 초안이 있나? ── 예 ──→ 아무것도 안 함 (다시 분석하지 않는다)
          │ 아니오
          ▼
┌─────────────────────┐
│ Vision OCR (배경 큐)  │──실패──→ "글자를 찾지 못했어요" · 캡처는 남는다
└─────────┬───────────┘
          │ 인식 결과를 캡처에 붙여 둔다 (재시도 시 재인식 안 함)
          ▼
┌─────────────────────┐
│ 백엔드 분석           │──실패──→ 원인별 문구 · 캡처는 남는다
│ POST /v1/analyze-…   │
└─────────┬───────────┘
          ▼
   TaskDraft 저장 (디스크에도)
          ▼
┌─────────────────────┐
│ 할 일 확인 (모달)     │
└─┬────────┬────────┬─┘
  │저장     │나중에   │버리기
  ▼         ▼        ▼
할 일 저장  초안 유지  초안 삭제
  │         (자동     + 캡처 삭제
  │          재표시
  │          안 함)
  ├──→ 알림 예약 (마감이 있고 켜 뒀으면)
  ├──→ 캘린더 저장 (켜 뒀으면) ──실패──→ "할 일은 저장했어요"
  └──→ 캡처 삭제 ← **여기서 처음 지운다**
```

**캡처가 지워지는 자리가 두 곳뿐인 것이 핵심이다.** 저장 성공과 버리기.
그 외의 모든 실패 경로에서 캡처는 상자에 남는다.

## 2. 플로우 — 텍스트로 시험하기

```
[＋] → 텍스트 분석 (키보드 자동)
     → 붙여넣기 → [분석하기]
     → 같은 확인 화면
```

스크린샷 경로와 **같은 확인 화면**으로 합류한다. 화면이 갈라지면 한쪽만 고쳐진다.
`sourceCaptureID == nil` 인 것만 다르고, 그래서 저장해도 지울 캡처가 없다.

## 3. 플로우 — 마감 확인과 처리

```
앱 열기
  ▼
지난 마감이 맨 위 (가장 오래 밀린 것부터)
  ▼
카드 탭 → 펼침 (다른 카드는 접힘)

  └─ 🗑 탭 → 삭제 → 알림 취소 + 캘린더 일정 거둠
```

## 4. 플로우 — 알림을 받고 나서

```
[알림] 치과 예약 확인 — 한 시간 뒤예요
  ▼ 탭
앱 열림 → refresh() → 마감 스택
  ▼
'오늘' 묶음 맨 위에 그 할 일
```

> 알림을 탭했을 때 해당 카드를 자동으로 펼치는 것은 아직 안 한다.
> `userInfo["taskID"]` 는 이미 넣어 두었으므로 라우팅만 붙이면 된다.

## 5. 유스케이스

### UC-1 · 예약 확정 문자를 할 일로

| | |
| --- | --- |
| 주체 | 예약 문자를 받은 사용자 |
| 사전 | 앱 설치, 백엔드 도달 가능 |
| 기본 흐름 | 문자 스크린샷 → 공유 → 담기 → 앱 열기 → 확인 → 저장 |
| 사후 | 할 일 1건, 알림 2건 예약, (선택) 캘린더 1건 |
| 대안 | 날짜가 모호하면 확인 화면이 경고를 먼저 보이고 캘린더 토글이 꺼진 채 뜬다 |
| 예외 | 백엔드 실패 → 캡처는 남고 다음에 다시 시도 |

### UC-2 · 광고 스크린샷을 잘못 담았다

| | |
| --- | --- |
| 기본 흐름 | 확인 화면 → [나중에 ⌄] → "이 제안 버리기" → 되묻기 → 버리기 |
| 사후 | 할 일 없음, 담아 둔 스크린샷 삭제 |
| 왜 되묻나 | 담아 둔 스크린샷을 함께 지우기 때문. 되돌릴 수 없다 |

### UC-3 · 앱을 안 열고 여러 장을 담았다

| | |
| --- | --- |
| 기본 흐름 | 3장 담기 → 앱 열기 → 순서대로 3번 분석 → 첫 초안 표시 → 저장 → 350ms 뒤 두 번째 → … |
| 사후 | 목록으로 돌아가지 않고 연달아 처리 |
| 대안 | "나중에 확인"을 누르면 그 건은 건너뛰고 다음 건 |

### UC-4 · 캘린더 권한을 거절했다

| | |
| --- | --- |
| 기본 흐름 | 확인 → 캘린더 토글 켬 → 저장 → 권한 거절 |
| 사후 | **할 일은 저장됨**, "캘린더에는 추가하지 못했어요 / 할 일은 Whenly에 저장했어요" |
| 왜 | 캘린더는 출력이지 원장이 아니다 (INV-CAL-1) |

### UC-5 · 저장 파일이 깨졌다

| | |
| --- | --- |
| 기본 흐름 | 앱 켜기 → 디코딩 실패 → 파일 격리 → 오류 알림 → 빈 목록으로 시작 |
| 사후 | 원본은 `tasks.corrupt-<시각>.json` 으로 남아 있다 |
| 왜 안 지우나 | 사용자의 데이터다. 복구를 시도할 수 있어야 한다 |

### UC-6 · 백엔드가 꺼져 있다 (개발 중)

| | |
| --- | --- |
| 기본 흐름 | 분석 실패 → "연결하지 못했어요. 캡처는 보관했어요" |
| 대안 | `WHENLY_OFFLINE=1` 로 다시 실행 → 규칙 기반 분석기 |
| 왜 자동 전환 안 하나 | 조용히 품질이 떨어지면 사용자는 AI가 나빠졌다고 생각하고, 우리는 백엔드가 죽은 줄 모른다 (INV-AI-1) |

## 6. 상태 전이 — 캡처

```
        enqueue()
   (없음) ──────→ [상자에 있음]
                      │
                      │ OCR 성공
                      ▼
                 [인식 완료]  ← recognizedText 가 붙는다
                      │
        ┌─────────────┼─────────────┐
        │ 분석 성공     │ 분석 실패    │
        ▼             │             │
   [초안 대기]         └──→ [상자에 있음] (다시 시도 가능)
        │
   ┌────┴────┐
   │저장      │버리기
   ▼          ▼
[삭제됨]   [삭제됨]
```

**`[초안 대기]` 에서 앱을 껐다 켜도 상태가 유지된다.** 초안이 디스크에 있기 때문이다.
이게 없으면 재실행마다 `[상자에 있음]` 으로 되돌아가 OpenAI를 다시 부른다.

## 7. 상태 전이 — 할 일

```
                    저장
       (초안) ──────────────→ [미완료]
                                │  ▲
                    toggle      │  │ toggle
                                ▼  │
                             [완료] ┘
                                │
                    delete      │
                                ▼
                            [삭제됨]
```

| 전이 | 알림 | 캘린더 |
| --- | --- | --- |
| → 미완료 (저장) | 예약 | 켰으면 생성 |
| 미완료 → 완료 | 전부 취소 | 그대로 둔다 |
| 완료 → 미완료 | 다시 예약 | 그대로 둔다 |
| → 삭제됨 | 전부 취소 | 일정도 거둔다 |

**완료 시 캘린더 일정을 지우지 않는 이유** — 캘린더는 "무엇을 했는가"의 기록이기도 하다.
지우면 지난 일정이 사라져 사용자가 되짚을 수 없다. 삭제는 "이 일 자체가 없던 일"이라는 뜻이므로 거둔다.

## 8. 상태 전이 — 마감 묶음

`now` 가 흐르면 저장된 값이 아무것도 안 바뀌어도 묶음이 옮겨 간다. 그래서 저장하지 않는다.

```
      마감 8일 뒤 → 7일 뒤 → 오늘 → (그 시각 지남) → 지난 마감
        [그 뒤]   [앞으로 7일] [오늘]              [지난 마감]
                                  │
                            완료 표시
                                  ▼
                               [완료]
```

`[날짜 없음]` 은 마감을 넣기 전까지 어디로도 가지 않는다.
