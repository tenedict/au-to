# IA — 정보 구조 · 내비게이션 · 용어 사전

> BMAD Phase 2 · `bmad-ux` → `DESIGN.md` 대응.

---

## 1. 사이트맵

```
CaptureTask
├─ 할 일 (탭 1 · 기본)            ← 원장
│   ├─ 확인할 할 일 N개 (배너)
│   │   └─ 할 일 확인 (모달)
│   │       ├─ 나중에 확인
│   │       └─ 이 제안 버리기 (되묻기)
│   ├─ 지난 마감      ▸ 카드 스택
│   ├─ 오늘           ▸ 카드 스택
│   ├─ 앞으로 7일     ▸ 카드 스택
│   ├─ 그 뒤          ▸ 접힘
│   ├─ 날짜 없음      ▸ 접힘
│   ├─ 완료           ▸ 접힘
│   └─ 텍스트로 추가 (모달)
│
└─ 캘린더 (탭 2)                  ← 읽기 전용 시점
    ├─ 이번 달 격자
    └─ 고른 날의 할 일

Share Extension (별도 프로세스)
└─ CaptureTask에 담기 → App Group 상자
```

---

## 2. 탭이 둘인 이유

| 탭 | 답하는 질문 | 고칠 수 있나 |
| --- | --- | --- |
| 할 일 | "지금 뭘 해야 하지?" | ✅ 원장 |
| 캘린더 | "그날 뭐가 있지?" | ❌ 읽기 전용 |

**같은 데이터를 두 각도에서 본다.** 시간축(캘린더)과 급함축(스택)은 서로 다른 질문에 답한다.
Apple 캘린더는 이미 훌륭한 시간축이므로, 앱 안의 캘린더는 "굳이 앱을 나가지 않게" 하는 정도만 한다 —
그래서 읽기 전용이다.

---

## 3. 내비게이션 규칙

- **탭은 늘리지 않는다.** 세 번째 탭이 필요해 보이면 그건 대개 새 묶음이거나 필터다
- **확인 화면은 언제나 모달이다.** 되돌아갈 곳이 목록 하나뿐이어야 "확인 안 한 것이 남았다"가 분명해진다
- **모달 안에서 모달을 열지 않는다.** 되묻기는 `confirmationDialog`로만
- 초안이 여러 건이면 **하나씩 이어서** 띄운다. 목록으로 돌려보내지 않는다

---

## 4. 홈의 정보 위계

```
1  확인할 할 일 N개        ← 사용자가 시작한 일이 아직 안 끝났다
2  경고줄 (담기 불가/알림 꺼짐)  ← 왜 안 되는지
3  지난 마감                ← 이미 늦었다
4  오늘
5  앞으로 7일
6  (접힘) 그 뒤 · 날짜 없음 · 완료
```

1번이 2번보다 위인 이유: **사용자가 방금 한 행동의 결과**가 시스템 상태보다 먼저 보여야 한다.

---

## 5. 카드가 접혔을 때 보이는 것

지갑 스택은 아래 카드가 위 카드의 아랫부분을 덮는다. 그래서 **위쪽 64pt 안에**
"무엇을 언제까지"가 다 들어가야 한다.

```
┌──────────────────────────────┐
│ ○  치과 예약 확인             │  ← 제목 (1줄)
│    📅 8월 5일 오후 2시  📅캘린더 │  ← 마감 + 배지
└──────────────────────────────┘
     ↑ 여기까지가 항상 보인다
```

메모·근거·삭제는 펼쳐야 보인다. 접힌 카드에 넣으면 다음 카드가 덮어 버린다.

## 6. 상태 표시 규칙

| 상태 | 기호 | 색 | 글자 |
| --- | --- | --- | --- |
| 지난 마감 | ⚠︎ `exclamationmark.triangle.fill` | 빨강 | "지난 마감" |
| 오늘 | ☀︎ `sun.max.fill` | 주황 | "오늘" |
| 앞으로 7일 | 📅 `calendar` | 강조색 | "앞으로 7일" |
| 그 뒤 | 🕐 `clock` | 청록 | "그 뒤" |
| 날짜 없음 | ? `questionmark.circle` | 회색 | "날짜 없음" |
| 완료 | ✓ `checkmark.circle.fill` | 초록 | "완료" |

**셋 다 항상 함께 나온다.** 색만으로 구분하면 색각 이상 사용자에게는 아무 정보가 아니고,
흑백 스크린샷에서도 읽히지 않는다.

## 7. 빈 상태

| 어디 | 문구 |
| --- | --- |
| 할 일 없음 | "아직 할 일이 없어요 / 스크린샷을 공유하거나 텍스트를 붙여 넣으면 할 일 후보를 만들어요." + [텍스트로 시험하기] |
| 그날 마감 없음 | "이 날 마감인 할 일이 없어요." |
| 메모 없음 (펼친 카드) | "메모가 없어요" |

빈 상태에는 **다음 행동**을 함께 둔다. "없습니다"로 끝나면 사용자는 앱을 닫는다.

## 8. 실패 문구

| 언제 | 문구 |
| --- | --- |
| App Group 못 씀 | "공유 상자를 열지 못했어요. App Group(…) 서명 설정을 확인해 주세요. 텍스트 붙여넣기는 그대로 쓸 수 있어요." |
| OCR 글자 못 찾음 | "스크린샷에서 글자를 찾지 못했어요. 글자가 있는 화면을 공유해 주세요." |
| 백엔드 응답 이상 | "OpenAI 분석 결과를 이해하지 못했어요. 캡처는 보관했으니 다시 시도해 주세요." |
| 백엔드 꺼짐 | "OpenAI 분석 서버에 연결하지 못했어요. 캡처는 보관했어요." |
| 요청 한도 | "요청이 많아요. 잠시 후 다시 시도해 주세요." |
| 캘린더 권한 | "캘린더 접근이 꺼져 있어요. 설정 > CaptureTask에서 접근을 허용해 주세요." |
| 기본 캘린더 없음 | "기본 캘린더를 찾지 못했어요. 캘린더 앱에서 기본 캘린더를 지정해 주세요." |
| 알림 권한 | "알림이 꺼져 있어요. 설정 > 알림 > CaptureTask에서 켜 주세요." |
| 파일 손상 | "…이(가) 손상되어 열지 못했어요. 원본은 …으로 옮겨 두었고, 목록은 빈 상태로 시작했어요." |

**규칙 세 가지.**
1. 무엇이 실패했는지 말한다
2. **잃지 않았다면 잃지 않았다고 말한다** ("캡처는 보관했어요")
3. 사용자가 할 수 있는 다음 행동을 말한다

## 9. 용어 사전

해요체. 사용자를 주어로. 기능 이름이 아니라 결과를 말한다.

| 쓴다 | 안 쓴다 | 왜 |
| --- | --- | --- |
| 담기 | 캡처, 저장 | 공유 시트에서 하는 행동 그대로 |
| 담아 둔 스크린샷 | 원본 이미지, 캡처 파일 | 사용자가 한 일로 부른다 |
| 확인할 할 일 | 대기열, 큐, 미승인 | 시스템 사정이 아니라 사용자 할 일로 |
| 확인 | 승인, 검토 | "승인"은 권한처럼 들린다 |
| 이 제안 버리기 | 거부, 삭제 | 제안을 버리는 것이지 데이터를 지우는 게 아니다 |
| 마감 | 데드라인, 기한, 만기 | |
| 지난 마감 | 연체, 미처리, overdue | |
| 앞으로 7일 | 이번 주 | 일요일에 "이번 주"는 오늘 하루로 읽힌다 |
| 날짜 없음 | 미정, 언젠가 | |
| 분석이 찾은 근거 | 프롬프트 결과, AI 응답 | 사용자에게 모델은 관심사가 아니다 |
| 확인이 필요한 부분 | 모호성, ambiguity | |
| 마감 알림 | 리마인더, 푸시 | 서버 푸시가 아니다 |
| 확인 요청 | 승인 요청, 알림 | "승인"은 권한처럼 들린다 |
| 스크린샷을 담았어요 | 할 일을 만들었어요 | 담은 시점에는 아직 아무것도 읽지 않았다 |
| 시간까지 지정 | 정확한 시간 | 종일과 대비되는 말 |
| Apple 캘린더에도 추가 | 캘린더 동기화 | 동기화가 아니라 한 번 내보내기다 |

### 금지

- "실패했습니다"만 적고 끝내기
- "오류가 발생했습니다" (무엇이? 내 것은 무사한가?)
- 기능 이름을 그대로 노출 (`TaskDraft`, `App Group`, `EventKit`)
  — 단, 사용자가 설정에서 찾아야 하는 이름은 예외 (`설정 > 알림 > CaptureTask`)
